# CampusFlow：课程意图解析、原生工具调用与知识库问答

CampusFlow 是一个学习 AI Agent 和 LLM 应用开发的项目。

当前包含三个阶段的原型：

- W1：将自然语言课程查询解析为结构化意图，并通过 Pydantic 校验。
- W2：由模型选择工具，本地 Python 校验并执行，将结果回传模型，支持多轮继续和终止。
- W3：加载模拟退课规则，完成切块、索引、检索与模型依据回答，并显示来源引用。

W2 工具循环与 W3 知识库问答目前使用独立入口，尚未组合成统一工作流。

代码基于导师参考示例完成保存、运行和学习，独立设计与实现能力仍在练习。

## 运行环境

已验证环境为 Windows PowerShell、Python 3.13.5。

依赖版本记录在 `requirements.txt`。

## 首次准备环境

在项目根目录打开 PowerShell：

```powershell
# 创建项目虚拟环境。
python -m venv .venv

# 使用项目环境的 Python 安装依赖。
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

已有可用的 `.venv` 时，无需重复创建。

## 配置 DeepSeek 密钥

在项目根目录创建 `.env`，填写：

```dotenv
LLM_API_KEY=replace_with_your_api_key
```

将占位符替换为自己的 DeepSeek API Key。

程序读取该配置，不在代码中保存真实密钥。
`.env` 已被 Git 忽略；仓库只保留不含真实密钥的 `.env.example`。

非空交互请求会调用真实模型，并按服务商用量计费。
自动测试使用模拟模型回复，不产生模型用量。

## W1：课程查询意图解析

```powershell
# 运行交互式意图解析。
.\.venv\Scripts\python.exe -X utf8 .\parse_intent_live.py
```

示例输入：

```text
帮我查本周五晚上3学分的专业课。
```

预期输出：

```json
{
  "intent": "search_courses",
  "time_range": "本周五晚上",
  "credits": 3,
  "course_category": "专业课",
  "requires_approval": false
}
```

当前字段规则：

| 字段 | 规则 |
| --- | --- |
| intent | 当前查询练习固定为 search_courses |
| time_range | 字符串，清理首尾空白后不能为空 |
| credits | 严格整数，且大于 0 |
| course_category | 通识课或专业课 |
| requires_approval | 严格布尔值；当前查询设为 false |

时间描述仍是文本，尚未转换为具体日期。

空输入不发送模型请求。程序对无效 JSON、字段校验失败、连接失败和超时给出提示。

## W2：原生多工具 Agent

```powershell
# 运行多轮工具调用入口。
.\.venv\Scripts\python.exe -X utf8 .\agent_loop.py
```

`-X utf8` 开启 Python UTF-8 模式。

看到“请输入课程请求”后，每次输入一条请求。

### 本地模拟课程数据

| 编号 | 名称 | 学分 | 类别 | 上课时间 |
| --- | --- | --- | --- | --- |
| C001 | Python 基础 | 3 | 专业课 | 周三下午 |
| C002 | 校园安全 | 2 | 通识课 | 周五晚上 |

### 示例请求与预期结果

| 请求 | 预期数据 |
| --- | --- |
| 查询 C001 的课程名称、学分和类别 | Python 基础、3 学分、专业课 |
| 查询 C001 的上课时间 | 周三下午 |
| 计算 C001 和 C002 的总学分 | 5 学分 |
| 查询 C001 和 C002 的课程信息、上课时间，并计算总学分 | 两门课程的信息和时间，总学分 5 |

模型选择的工具顺序和最终措辞可能不同。

### 工具及执行规则

| 工具 | 用途 |
| --- | --- |
| get_course_info | 根据编号查询课程信息 |
| get_course_schedule | 根据编号查询上课星期和时间段 |
| calculate_credit_total | 根据编号列表计算总学分 |

模型只提出工具名称和参数，实际执行的是本地 Python 程序。

程序检查工具白名单、解析参数 JSON，并使用 Pydantic 校验参数。
未知工具或非法参数被拒绝，拒绝原因作为工具结果回传模型。

每轮执行结果加入消息历史，下一轮模型根据结果决定继续调用工具还是回答。

总学分计算中，重复编号只计一次。
任意课程不存在时，计算失败，不返回部分总数。

### 终止与日志

- `max_steps=4` 限制模型请求轮数。
- 每轮最多处理三个工具调用。
- 第 4 轮给出正常回答时，可以成功结束。
- 第 4 轮仍请求工具时，Python 直接提示停止，不执行这批工具，也不发送第 5 轮请求。
- 网络失败、超时或响应截断等情况按程序规则停止并提示。

工具日志记录名称、调度状态、业务状态和本地调度耗时。

`dispatch_status=completed` 表示调度处理完成，不保证业务成功。

`business_status` 的含义：

- `success`：业务成功。
- `failed`：业务失败，例如课程不存在。
- `not_executed`：请求被拒绝，业务没有执行。

`elapsed_ms` 不包含模型网络请求耗时。

## W3：模拟规则知识库问答

### 功能与处理流程

RAG（检索增强生成）先检索相关资料，再让回答模型根据检索结果组织答案并引用来源。

当前实现了关键词检索和向量检索两条基础流程，以下使用向量问答入口。

准备阶段：

模拟文档 → 按条款切块 → 计算文档向量 → 保存索引。

查询阶段：

用户问题 → 计算问题向量 → 与已保存的文档向量比较 → 选择候选块 → 模型依据候选回答 → 显示来源。

查询时只计算新问题的向量，不重新计算全部文档向量。

### 资料与配置

- 资料：`data/public_docs/drop_course_policy.md`。
- 当前构建入口固定读取这一份文档，不会自动扫描目录中的所有文件。
- 内容完全虚构，仅用于学习与测试，不代表真实学校规定。
- 文档版本：1.0；规模：1份文档、3个条款块。
- 切块：按二级标题切分，保留完整条款，并在每块中保留公共前言。
- 来源字段：文件路径、文件名、章节和块编号。
- 向量模型：`BAAI/bge-small-zh-v1.5`，512维。
- 向量库依赖：`fastembed==0.9.0`，本地CPU计算。
- 编码方式：`raw_text`；相似度：余弦相似度。
- 模型文件缓存：`.venv/model_cache/`。
- 文档向量索引：`data/index/vector_index.json`。
- 回答模型：`deepseek-flash`，关闭thinking，`max_tokens=512`。
- 回答请求：非流式，超时30秒，关闭自动重试。
- 检索和问答脚本默认 `--top-k 2`；本轮固定10题评测显式使用 `--top-k 1`。
- 当前未设置相似度过滤阈值。

模型缓存保存编码模型文件；文档索引保存文档块、来源、向量和编码配置，两者用途不同。

### 使用前提

在项目根目录的 PowerShell 中执行下列命令。

先按本README的环境准备说明安装 `requirements.txt`。
已有可用环境时无需重复创建或安装。

首次使用向量模型时可能需要联网下载模型文件。
文档与问题的向量在本地计算；最终回答通过DeepSeek接口生成。

完整问答沿用前面的 `LLM_API_KEY` 配置。
只构建索引或只做向量检索，不调用DeepSeek回答接口。
完整问答会将问题和检索到的候选正文、来源信息发送给回答服务，并产生模型用量。

### 1. 构建文档向量索引

仅在索引尚未建立，或资料及相关处理配置改变后执行：

```powershell
# 加载模拟资料、切块、计算文档向量并保存索引
.\.venv\Scripts\python.exe .\rag_build_vector_index.py
```

当前版本的正常结果应显示：

- 读回块数为3。
- 每块向量维度为512。
- 模型和FastEmbed版本正确。
- 配置、正文、来源和向量检查通过。

该命令会更新 `data/index/vector_index.json`。
已有与当前资料和配置一致的索引时，无需为每次提问重新构建。

### 2. 只查看检索候选

```powershell
# 只检索并打印候选，不调用回答模型
.\.venv\Scripts\python.exe .\rag_vector_retrieve.py '退课由谁审查？' --top-k 1
```

引号内是问题；`--top-k 1` 表示最多返回一个候选块。

输出包含相似度、块编号、章节、来源路径和正文。
已观察到该问题返回第2条，可从正文核对任课教师审核的规定。

相似度表示候选与问题的相关程度，不是答案正确率。
当前没有分数过滤，非空索引也可能为无关问题返回候选。

### 3. 根据候选生成回答

```powershell
# 检索候选，再发起一次回答模型请求
.\.venv\Scripts\python.exe .\rag_vector_answer.py '退课由谁审查？' --top-k 1
```

正常回答应说明由任课教师审核，并引用支持这一结论的第2条。

程序显示：

- 模型回答。
- 引用编号检查结果。
- 本次候选对应的文件、章节、路径、块编号和相似度。
- 候选是否被回答实际引用。

`[S1]` 是本次请求中的临时来源编号，不是永久文档编号。
需要查看该次输出的来源映射，确认它实际对应哪一条。

引用编号检查只确认所用编号是否存在。
回答是否保留条件、是否遗漏信息、原文是否支持结论，仍需人工核对。

资料不足时应说明无法确认。
“没有规定”不能推断为允许、禁止或免费。
对于部分有依据的问题，应分别回答确定部分和无法确认部分。

### 资料更新与索引维护

当前索引是构建时的资料快照，不会随Markdown原文自动更新。

- 修改原文、调整切块规则或更换编码模型后，应重新构建文档向量索引。
- 改变编码方式或FastEmbed版本时，应核对兼容性并重新构建匹配当前配置的索引。
- 仅修改问题或调整Top-K，不需要重新计算已有文档向量。
- 调整Top-K后得到的评测结果，应作为新配置单独记录。
- 当前查询会检查索引中的编码配置，但不会自动检测原文是否已经修改。
- 两个模型即使都输出512维向量，也不代表向量空间兼容。
- 若还使用关键词问答，需要同步重建对应的关键词索引；两个索引不会互相更新。

### 固定10题验证

详见[W3固定10题验证](data/eval/w3_fixed_10.md)。

本轮统一使用Top-K=1：

- 10题已人工核对，9题通过，Q06未通过。
- Q06同时询问审核人和提交截止时间，需要第2条和第1条。
- 实际只检索到第1条，截止时间正确，审核人无法确认。
- 模型没有编造缺失信息，但完整答案仍不满足要求。
- Q01、Q10复用学习对话中的既有截图。
- Q02–Q09原始输出保存在 `data/eval/runs/w3_top1/`。
- 9/10仅代表该固定问题集的本轮结果，不代表真实校园场景的准确率。
- Top-K优化对比尚未完成，不提前宣称增加候选一定提高效果。

### W3当前边界

当前仅使用一份模拟文档，没有完成多文档、大规模语料或复杂Markdown切块验证。

向量检索采用JSON保存和逐块比较，尚未接入专用向量数据库。

没有实现原文变更自动检测、自动索引更新或重排序。

候选存在、分数较高、引用编号有效和退出码0，都不能单独证明回答正确。

W3目前采用固定问题的手工验证，尚未建立W3专用自动评测套件。
已有W1、W2自动测试不覆盖W3问答质量。
