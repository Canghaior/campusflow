# W1 学习笔记：Prompt、Schema 与自由文本输出

## 1. 三个概念各自做什么

| 概念 | 作用 | 本项目中的例子 |
| --- | --- | --- |
| Prompt：提示词 | 告诉模型要做什么、怎样回答 | 提取课程查询信息，只返回 JSON |
| Schema：数据规则 | 定义字段、类型、必填要求和允许值 | 学分必须是严格整数，且大于 0 |
| 普通自由文本输出 | 用自然语言表达回答，方便人阅读 | 用一句中文解释 API 是什么 |

Prompt 中的要求需要模型遵循。Schema 校验由程序执行，用于检查实际收到的数据。

## 2. 为什么使用 JSON 输出

自由文本的表达方式可能变化，程序直接提取固定字段比较困难。

JSON 使用固定字段表达信息，方便后续程序读取。例如课程查询包含时间、学分和课程类别。

本项目开启 JSON 输出模式，并在 Prompt 中说明字段要求和示例。JSON 输出模式约束回复格式，字段规则仍由 Pydantic 检查。

## 3. JSON 格式正确，不代表字段合规

| 学分内容 | JSON 语法 | 当前学分规则 |
| --- | --- | --- |
| 数字 3 | 合法 | 通过 |
| 字符串 "3" | 合法 | 失败：不是严格整数 |
| 数字 0 | 合法 | 失败：没有大于 0 |
| 缺少学分字段 | 可以合法 | 失败：缺少必填字段 |

缺少逗号属于 JSON 语法错误，会在 json.loads() 时被发现。

字段缺失、类型错误或取值不合规，会在 UserIntent.model_validate() 时被发现。

## 4. 当前程序的数据流程

用户输入课程请求 → 模型返回 JSON 文本 → json.loads() 转成字典 → Pydantic 校验成 UserIntent 对象 → 导出字典 → 输出 JSON 文本。

对应的 Python 类型变化为：

str → dict → UserIntent → dict → str

校验成功后才能输出正常结果；失败时程序提示原因并退出。

## 5. 本次实际成果

在导师提供的参考示例基础上，我保存并运行了课程意图解析 CLI，验证了不同课程请求和空输入。

我运行了 7 个模拟自动测试，结果全部通过。测试覆盖正常回复、空输入、缺字段、非法类型、无效 JSON、连接失败和超时异常。

Mock 用模拟客户端替换真实客户端，使测试可重复运行，不产生模型用量。

断言检查实际结果是否符合预期。例如 assert_not_called() 要求请求调用次数为 0，assert_called_once() 要求恰好为 1。

## 6. 当前验证的范围

Schema 通过说明字段符合规则，不能保证模型对用户意思的理解一定正确。

模拟测试检查本地流程和异常处理，不证明真实模型的提取准确率，也没有验证实际断网或超时时间。

当前原型只解析课程查询意图，尚未实现课程数据库查询、审批或申请提交。
