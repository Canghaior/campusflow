# W2 学习笔记：工具调用、Agent Loop 与 ReAct

## 1. 各部分的职责

| 部分 | 职责 |
| --- | --- |
| 模型 | 根据目标和已有结果，提出工具请求或组织回答 |
| 工具函数 | 执行课程查询、时间查询或总学分计算 |
| 参数 Schema | 检查必填字段、类型和取值约束 |
| 工具调度入口 | 检查白名单，选择带校验的执行函数 |
| 消息历史 | 保存用户目标、工具请求及对应结果 |
| Agent Loop | 控制继续请求、结果回传和停止 |
| 工具日志 | 记录工具名称、处理状态及本地调度耗时 |

模型提出调用信息，实际执行 Python 函数的是本地程序。

## 2. 当前循环的主要流程

```text
用户目标 + 消息历史
        ↓
请求模型
        ↓
是否请求工具？
├─ 否：返回正常回答 → 结束
└─ 是：检查步数上限
        ├─ 已到上限 → 停止，不执行新工具
        └─ 未到上限
                ↓
        白名单检查、参数解析与校验
                ↓
        工具执行结果或拒绝结果
                ↓
        按调用 ID 加入消息历史
                ↓
        再次请求模型
```

tool_call_id 用于把工具结果对应到模型提出的那次调用。

参数错误可以作为反馈交给模型；网络失败、响应截断等情况按当前程序规则停止并提示。

## 3. ReAct 与函数调用的关系

ReAct 强调推理与行动交替，并根据观察结果更新下一步选择。

普通函数调用完成一个确定操作；工具调用协议表达模型希望执行的动作；Agent Loop 管理多轮执行。

当前项目具备工具执行、结果观察和继续决策的循环基础，但没有记录论文中的显式推理轨迹，不能称为完整论文复现。

参考：[ReAct 原始论文](https://arxiv.org/abs/2210.03629)

## 4. 已验证的实践成果

在导师完整参考示例基础上，我保存并运行了三个本地工具、参数校验、调度入口、工具说明和 Agent Loop。

真实模型能够请求查询 C001 的上课时间，本地返回周三下午，模型最终回答一致。

真实总学分请求能够选择 calculate_credit_total，传入 C001 和 C002，得到 5 学分。

组合请求曾在第 3 轮正常汇总并结束。

我运行了六项循环模拟测试，全部通过。它们覆盖：

- 三个工具及消息历史、调用 ID。

- 步数耗尽时停止新工具执行。

- 最后一轮正常回答。

- 未知工具和非法参数反馈后修正。

- 非法 JSON 的错误回传。

- 截断响应不执行工具。

测试模拟模型请求，保留真实本地工具，不产生模型用量。

## 5. 日志与限制

dispatch_status=completed 表示调度处理完成，不保证业务成功。

business_status 分别表示：

- success：业务成功。

- failed：业务结果失败，例如课程不存在。

- not_executed：请求被拒绝，业务没有执行。

elapsed_ms 测量本地工具调度耗时，不包含模型网络请求。

当前 max_steps=4 限制模型请求轮数，每轮最多处理三个工具调用。最后一轮仍请求工具时停止；最后一轮正常回答可以成功结束。
