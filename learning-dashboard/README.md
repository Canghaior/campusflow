# CampusFlow 本机学习进度页

页面直接读取项目根目录的 `LEARNING_PLAN.md` 和 `LEARNING_PROGRESS.md`，展示当前任务、12 周路线、四次阶段验收、每周安排和学习记录。导师更新进度文件后，打开中的页面每 5 秒检查一次变化，也可以手动刷新。

## 打开页面

在项目根目录双击 `打开学习进度.cmd`。它会在后台启动本机服务并打开浏览器。已经启动时复用现有页面地址。

也可以在项目根目录执行：

```powershell
python learning-dashboard/server.py --open-browser
```

默认地址为 `http://127.0.0.1:8765/`。只有本机可以连接。运行需要 Python 3.10 或更新版本，不需要额外安装依赖。终端方式运行时按 Ctrl+C 关闭；后台启动的服务在电脑重启后结束，再双击入口即可重新启动。

## 进度与学习记录

- 当前任务与已验收状态来自 `LEARNING_PROGRESS.md`。浏览后面的周次只查看计划，不改变学习位置。
- 本周已验收步骤按当前周子任务表中“已验收”的行计数；阶段验收按四个阶段表中的已验收状态计数。
- 页面填写的用时、心得和成果写入根目录 `LEARNING_JOURNAL.json`，刷新或重启后仍可读取。这个文件在第一条真实记录保存时创建。
- 学习记录由学习者自述，保存后状态为 `pending_review`，不自动改变任务验收状态。导师读取并核对实际成果后，更新进度 Markdown；需要标记已 Review 时，将相应记录状态改为 `reviewed`。
- 累计用时仅累计填写的学习记录。没有记录时显示“—”，不估算已经学习的时间。

原计划是课程范围，进度 Markdown 是验收依据，Journal 是学习者的自述与待 Review 材料。页面代码由助手为跟踪学习而制作，不计入学习者的 CampusFlow 业务代码和 W1 自动测试成果。

## 导师继续维护

继续沿用现有 Markdown 表头。进入下一周时，更新顶部的当前周、当前任务、证据和下一步，并添加 `## W2 当前任务拆分` 等对应章节。子任务表仍使用“子任务、目标、最低验收、状态”四列，任务编号如 `W2-T1.1`。周路线、阶段验收和学习记录也同步更新。

已讲解和已掌握分别记录；部分步骤完成时不要把整个任务标为已验收。主计划里的复选框只在完整条目验收通过后勾选。

## 本机验证

```powershell
python -m unittest discover -s learning-dashboard/tests -v
node --check learning-dashboard/dist/app.js
```

测试在独立临时目录中验证文件联动、记录保存、重复请求、输入校验和本机写入限制，不向真实学习记录写入测试数据。浏览器功能包括周次查看、文档阅读、记录表单和窄屏布局。
